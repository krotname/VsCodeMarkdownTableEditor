# Исправление и проверка Markdown Table Editor для VS Code

Unit-тесты core и реальные Extension Host E2E закрывают разные ошибки. В аудите
03.10.2026 парсер был корректен на части входов, но извлечение диапазона и
отложенное автоформатирование повреждали соседний текст или затрагивали другую
таблицу. Проверять нужно и результат таблицы, и фактическую правку документа.

## Core и общий контракт

`src/core.ts` не импортирует VS Code. Общий regression-case добавляется одновременно
в `test-fixtures/markdown-table-core-golden.json`, C++-фикстуру Npp и Java-фикстуру
IDEA. Семантическое сравнение JSON и матрица CSV/TSV —
[в ранбуке Npp](https://github.com/krotname/NppMarkdownTableEditor/blob/master/docs/RUNBOOK.md);
команды Java — [в ранбуке IDEA](https://github.com/krotname/IdeaMarkdownTableEditor/blob/main/docs/RUNBOOK.md).

Для неровного заголовка выбирать грамматику по логическим записям, с учётом body.
TAB внутри quoted CSV-продолжения не создаёт TSV-запись; quoted TAB в поздней
TSV-ячейке не заставляет выбрать CSV. Не заменять алгоритм проверкой наличия
запятой/TAB в физической строке. Неоднозначный вход проверять против существующего
контракта до изменения политики выбора разделителя.

## Диапазоны `src/extension.ts`

Извлечение блока должно использовать ту же грамматику, что и преобразование.
Первый проход собирает кандидата; после определения разделителя требуется
повторный проход с выбранной грамматикой и началом заголовка.

Обязательные E2E при изменении границ:

- Курсор внутри quoted многострочного заголовка/значения и после закрывающей кавычки.
- Неровный одноколоночный заголовок, одноколоночная запись в середине и на краях.
- Полностью пустая TSV-запись и строка только из TAB после заголовка с запятой.
  Предварительный выбор CSV не должен обрывать поиск до определения грамматики.
- CSV с TAB как частью значения/отступа; кавычка после TAB в CSV и после запятой
  в TSV не должна поглощать соседний прозаический текст.
- Выделение, заканчивающееся одним или несколькими LF/CRLF: весь суффикс
  сохраняется, соседний текст остаётся вне range. Обработка суффикса линейная.
- Парная проверка настоящей CSV: строка только из TAB после её таблицы остаётся
  вне преобразования. Исправление TSV не должно расширить CSV-range.

Каждый тест сравнивает полный документ, а не только содержимое конвертированной
таблицы. Один успешный вызов core не заменяет проверку команды с курсором/range.

## Отложенное автоформатирование

1. Хранить debounce и подавление собственных правок по документу. Таймер одного
   документа не отменяет запрос другого видимого редактора.
2. Обрабатывать изменённые offsets и selections, в том числе многострочные и
   multi-cursor edits. Форматировать затронутую таблицу после обновления документа.
3. Не переносить focus и selection в другой split editor. Проверять два одновременно
   видимых документа, в том числе редактирование неактивного документа.
4. Проверять вставку/разделение заголовка и удаление целой body-строки. Смещение
   таблицы из-за редактирования прозы само по себе не требует её форматирования.
5. Undo/Redo не создаёт новую formatting edit. Отменять запрос затронутой таблицы,
   сохраняя/пересчитывая запросы незатронутых таблиц.
6. Удаление или замена заголовка инвалидирует его отложенный anchor. Соседняя
   таблица, оказавшаяся на том же offset, не наследует старый запрос.

Для timer-багов воспроизводить последовательность edits до выполнения debounce,
затем проверять документ, undo stack, focus и selection в реальном Extension Host.

## Локальные проверки

Из корня репозитория, с Node.js из текущего CI и lockfile:

```powershell
npm ci
npm run check
npm run test:coverage
npm run test:e2e
```

`test:e2e` собирает расширение, скачивает стабильный VS Code и запускает отдельный
Extension Host. На Linux без графического сеанса:

```bash
xvfb-run -a npm run test:e2e
```

Для изменения упаковки:

```powershell
npm run package
npm run test:vsix
```

`test:vsix` проверяет установку пакета в чистый профиль. Не включать `dist`, `build`,
coverage и скачанные runtimes в Git. Не менять версию инструмента упаковки ради
сбоя, который не связан с ним; сохранять согласованность `package.json`/lockfile
при интеграции параллельных PR.

При adapter-only изменении запускать typecheck и соответствующие реальные E2E.
При core-изменении дополнительно проверить unit/coverage и паритет всех портов.
Обязательные CI остаются обязательными; после успешных целевых проверок повторять
локальные тесты только при новой правке или конкретной нерешённой проблеме.

## PR, публикация и доказательства

Ветка `feature/…` от свежего `origin/main`; после проверок commit/push/PR, CI точного
финального head, применимое ревью, merge и checks merge SHA. Синхронизировать свой
checkout. Docs-only diff не требует внешнего ревью; build CI может быть исключён
path filter. Исключённый run не называть успешным run.

Build/VSIX artifact и merge bugfix не означают новую публикацию в Marketplace.
Для релиза следовать [CONTRIBUTING](../CONTRIBUTING.md#releasing) и
[MARKETPLACE_SUBMISSION](../MARKETPLACE_SUBMISSION.md), сверить опубликованную
версию отдельно от CI.

Историческая проверка [PR #39](https://github.com/krotname/VsCodeMarkdownTableEditor/pull/39),
03.10.2026: 110 unit-тестов, 45 реальных E2E; coverage 98.05% lines,
87.35% branches, 99.32% functions. CI финального head и merge SHA прошёл, включая
E2E на Windows/Linux и VSIX. Эти числа описывают тот коммит, а не фиксированный gate.
